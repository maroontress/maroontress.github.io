「定石」を過剰に適用してしまう

ソースコードに関する質問を生成AIに尋ねてみた。プログラミング言語はJavaで、具体的には次の質問だ:

Javaの`Optional<String>`について教えてください:

```java
// Optional<U> f(String);
// Optional<U> g();
// ※ f()もg()もnullを返さない
Optional<String> maybeString = ...;
```

のとき、次のコードは等価ですか?

```java
var t = (maybeString.isPresent())
    ? f(maybeString.get())
    : g();
```

```java
var t = maybeString.map(s -> f(s))
        .orElseGet(() -> g());
```

読者が実験しやすいように、プロンプト全体をコードブロックにした。人間向けに次に再掲さいけいする:

JavaのOptional<String>について教えてください:

// Optional<U> f(String);
// Optional<U> g();
// ※ f()もg()もnullを返さない
Optional<String> maybeString = ...;

のとき、次のコードは等価ですか?

var t = (maybeString.isPresent())
    ? f(maybeString.get())
    : g();

var t = maybeString.map(s -> f(s))
        .orElseGet(() -> g());

要するに、maybeStringがOptional<String>型であるとき、次の二つは等価かどうかを尋ねた。

  • maybeString.isPresent() ? f(maybeString.get()) : g()
  • maybeString.map(s -> f(s)).orElseGet(() -> g())

答えはYesであり、現時点（2026年7月現在）では、以下の生成AIは質問に正しく答えられている:

  • OpenAI GPT-5.5の回答
  • Claude Sonnet 5 (Middle) の回答

⚠️ 最初のプロンプトでOptionalをタイプミスでOptinalと書いたが、生成AIはそれを理解した上で回答してくれたようである。

質問に正解できたなら良いではないか、と思うかも知れないが、どちらの生成AIも間違った提案を勧めてきた。しかも、それらの提案は全く同じ内容だった。いったい、どういうことだろう。

「間違った提案」の中身

詳しくは上記の会話を確認してもらうと良いが、二人とも次のように勧めてきた:

map(…).orElseGet(…) よりも flatMap(…).or(…) を使う方が良い

しかし、flatMap(…).or(…) を使うと、元々の三項演算子版と意味が変わるのではないかと、具体例を挙げて尋ねると、flatMapを使った場合は意味が変わる（等価ではない）ことを認めた。さっきは「flatMap でも同じ結果になる」と言っていたことを尋ねると、謝罪して訂正した。

flatMapで結果（意味）が変わるのは、次の2つが満たされるケースだ:

  • maybeStringがpresent（isPresent()が真を返す）
  • f()がOptional.empty()を返す

両者とも、初見ではなぜかこれを見落として、flatMap(…).or(…) を勧めてきたのだ。

その1年前

この質問は、およそ1年前の2025年9月にも実施した。この時は、三項演算子版とmap(…).orElseGet(…)版が等価であることさえ説明できなかった。次はその時の記録である:

  • OpenAI GPT-5の回答
  • Claude Opus 4.1 +じっくり考える の回答
  • OpenAI GPT-5 Thinkingの回答

最後の「OpenAI GPT-5 Thinking」だけが等価であることを回答できたが、先ほどのOpenAI GPT-5.5同様に「flatMapを推して」しまった。

このとき、数ヶ月経てば（モデルが改良されるので）、生成AIは正しい回答をするようになるだろうと考えていた。しかし、1年経っても、まだ「flatMapを推す」癖は抜けていない。

10時10分バイアス

生成AIにアナログ時計の画像を作成させると、ほぼ10時10分の時計を描く癖がある。これは、10時10分バイアスと呼ばれ、学習データにおけるアナログ時計の画像の多くが10時10分を指していることに起因する。生成AIは、学習データにおける頻出パターンを「定石」として覚えてしまうのだ。

  • Nano Banana 2 Liteが作成したアナログ時計の例

10時10分バイアスの解説は、次のリンク先で詳しく説明されている。

  • 10時10分バイアスの解説

アナログ時計が10時10分であることに問題は無いが、3時25分のアナログ時計を描くように指示しても10時10分の時計を描いてしまうとなると問題である。OptionalのflatMapは、アナログ時計の10時10分のようなもので、学習データにおける頻出パターンを「定石」として覚えてしまうことが、間違った提案を勧める原因になっているのだろう。

まとめ

これはポチョムキン理解の良い例である。生成AIは、「よくあるパターン」をむやみに勧める癖がある。しかし、提案の内容を検証させると、間違いであることを認める。今や、生成AIは「正しい答え」を出す判断はできるが、間違ったことをお勧めしてきて、平然と謝罪することもある。つまり、生成AIは「正しい答え」と「間違った提案」を精査できるが、正しいかどうかはさておき、頻出パターンの提案を勧めがちである、ということだ。

そして「よくあるパターン」とは学習データにおける頻出パターンである。特に、ポイントになるのは、OptionalのmapとflatMapのように、初心者や中級者は使わない機能である。これらは、おそらく全体で学習したコードにはあまり出現しておらず、flatMapの利用例がmapよりも多く偏っているのではないかと推測される。

  • 1年間の追跡比較が説得力を強めています。2025年9月時点では等価性の判定自体ができず、2026年7月時点では判定はできるようになったが「flatMapを推す」癖は変わらない、という進捗の非対称性を示しているのが良いポイントです。「モデル性能の向上」と「特定の誤った既定選択の解消」が別軸である、ということを実データで示しているのは、単なる「AIは間違えることがある」という話より一段深いです。
